Concept

Overview: how the signal gets to the DUT

Patterns go from the PC into each RFSoC card. The card generates the outputs in two ways: an RF-DAC for arbitrary waveforms and a GTY serializer for fast one-bit pulses. The carrier board amplifies both to 3 V, sets each channel's DC level, and drives the DUT. One sync unit keeps all four modules on the same clock.

Three design rules carry over to layout: route all eight one-bit lanes as length-matched 100 Ω pairs; keep each output channel as a strip that runs straight to its front-panel SMA; and give the DC-level buffers their own ground return so DC current stays out of the RF ground under the amplifiers.

Pulse fidelity: lowest frequency and edge speed

Which parts set the lowest frequency and the edge speed, and what does a 500 ps, 3 V pulse look like after the chain? Every coupling capacitor, balun and bias choke adds a high-pass corner. The source edge, the amplifier and the balun set the high end.

What the low corner does to a pulse

A high-pass corner fL makes the top of a pulse sag. Over a pulse of width τ the top drops by 1 − exp(−2π fL τ). For 500 ps even a 1 MHz corner costs only 0.3 %, so short pulses pass AC coupling well. The low corner matters for long pulses, slow DC-level steps and long patterns.

After AC coupling, a unipolar pulse train settles so that its average is zero. The baseline moves down by duty × amplitude: 500 ps every 100 ns at 3 V gives 15 mV. Corners well below 1 / period keep this shift. Corners near or above it let the baseline recover between pulses.

What sets the edge

The 10–90 % rise time is about 0.35 / bandwidth. The GTY edge (about 20 ps), the RF-DAC (about 60 ps), the amplifier and the balun each limit the bandwidth. Their rise times add roughly as root-sum-square.

The carrier parts are on the Carrier schematic: T1, L1/L2/L5 and C1–C4 on the one-bit outputs, C11 and L10–L12 on the DAC outputs. The card's own DAC path is in Card findings.

Formulas used here

  • Capacitor into 50 Ω: f = 1 / (2π · 50 Ω · C). Choke across 25 Ω: f = 25 Ω / (2π L).
  • Droop over a pulse of width τ: 1 − exp(−2π fL τ). For several corners, use the sum of the corners.
  • Cascade −3 dB: solve |H(f)|² = ½ with |H|² = Π f² / (f² + fi²) for the high-pass corners and Π 1 / (1 + (f / fi)²) for the low-pass limits.
  • Rise time 10–90 % ≈ 0.35 / BW. Parts combine roughly as root-sum-square.
  • Baseline shift after AC coupling = duty × amplitude (0.5 % × 3 V = 15 mV).
  • P1dB for a Vpeak pulse into 50 Ω: 10·log10(V² / (2 · 50 Ω) / 1 mW). 3 V needs 19.5 dBm, 4 V needs 22 dBm.

Step 5

Sync and timing

All modules have to start their patterns on the same clock edge. The trick is that the trigger only arms each module. The actual start is the next SYSREF edge, which comes from one source and reaches every card with the same delay. So the trigger can arrive anywhere inside a 200 ns window and every module still starts on the same cycle.

Trigger alignment

TRIG reaches each module a few ns apart because cables and receivers differ. With SYSREF gating the trigger only arms the module and all modules start on the next SYSREF edge, while starting straight on TRIG copies the arrival spread into the outputs, rounded to the 4 ns fabric clock.

Start-up sequence

  1. The sync unit locks its LMK04832 to the OCXO and starts SYSREF.
  2. On each carrier, U21 locks to REF and aligns to SYSREF. The GTY clock is now frequency-locked to the shared reference.
  3. On each card, the LMK04828 locks to REF on J66 and re-clocks SYSREF from J35.
  4. Each card runs RF-DAC multi-tile sync and reports the measured latency to the PC.
  5. The PC sets one common target latency for all 32 DACs, so every card pads to the slowest.
  6. GTY lanes come up with TX buffer bypass and phase alignment; the PL loads the patterns.
  7. The PC arms the TRIG re-timer. Every module starts on the same SYSREF edge after TRIG.
  8. Apply the stored skew table (bit shifts and interpolator steps), or measure a fresh one.

Multi-board signals

Only the trigger is timing-critical, and it travels on coax from the sync unit. Everything else between modules (ready flags, latency reports, the common target latency) goes over Ethernet through the PC, where a few milliseconds don't matter.

The trigger has to be valid before the SYSREF edge it should start on. The PL samples it at 250 MHz, so a 200 ns SYSREF period leaves a very wide margin. If a hardware ready line is ever needed, IO8/IO9 are free and can be wired as an open-drain bus through the sync unit.

    Build · Mechanics

    Mechanical concept

    The carrier lies flat in a small aluminium box and the HamGeek card stands upright in its slot, like a card in a PC. The front panel carries only the 16 RF outputs, so the cables to the DUT stay short and tidy. Power, Ethernet and the sync cables all go to the rear. Air enters at the front and leaves through a rear fan, passing the card's heatsink on the way.

    All dimensions are estimates. HamGeek doesn't publish the card size, so this assumes a full-height card about 250 mm long with a dual-slot heatsink. Measure the card when it arrives and rescale.

    What stays the same

    The carrier design, the firmware image and the start-up sequence. Every module is identical, so a spare module can replace any other after a skew re-calibration.

    What changes

    The number of sync outputs: the LMK04832 has 14 outputs, enough for 4 modules (4 REF + 4 SYSREF) with spares. 8 modules need 16 outputs, so add buffers. Cable sets, supply size and rack space grow linearly.

    Mixing with the existing ZCU216

    The ZCU216's CLK104 can take REF and SYSREF from the same sync unit, adding 16 DAC channels to the array. It needs its own front end (an RFMC mezzanine), and its outputs will differ slightly from the HamGeek channels, so calibrate it as a separate group.

    DAC-only modules

    If a module only needs RF-DAC outputs, leave the one-bit front ends unpopulated and skip the GTY rework. The 16-DAC option then costs two cards plus two lighter carriers.

    Roadmap

    Roadmap and open items

    Five phases take the design from one card on the bench to a calibrated array at the DUT. Each phase ends at a gate, and each open item belongs to the phase that has to close it.

    1. P0

      Evaluate one card

      2–4 weeks

      Goal. Prove that one HamGeek card does what the design assumes before we draw the carrier.

      Tasks

      • Bring up one HamGeek card: power, JTAG, PCIe and the RF-DAC tiles.
      • Lock the LMK04828 to an external 10 MHz REF on J66 and check that J35 takes SYSREF.
      • Run GTY TX0–3 at 20 Gb/s raw from a 156.25 MHz refclk on the PCIE_CLK pins.
      • Do the TX4–7 rework (fit C632–35 and C1022–25, remove the QSFP2 0 Ω parts) and repeat the 20 Gb/s test.
      • Measure the card DAC path (0.1 µF, TCM2-63WX+, SSMC) from 100 kHz to 6 GHz.
      • Decide between the UWB2-50E balun swap and the single-ended bypass.

      Open items

      Exit gate. Eight GTY lanes run at 20 Gb/s, the DAC path is measured, and the balun choice is written down.

      Stages Card findings Module Sync & timing
    2. P1

      Carrier prototype

      One module

      Goal. Turn one card into a working module: 3 V outputs into 50 Ω with a DC level on every channel.

      Tasks

      • Draw the carrier schematic and layout: slot J1, SSMC inputs J2–J9, AFE, PA and power.
      • Build both DAC path variants: the UWB2-50E transformer (T1) and the single-ended option (R1/R2).
      • Test the staged chokes (L1, L2, L5) and gain blocks (U1, U2) at low frequency on a test board.
      • Reach 3 V into 50 Ω on all 8 DAC and 8 one-bit outputs.
      • Bring up the DC-level stage: U31/U32 AD5675R and the U33–U40 buffers.

      Open items

      Exit gate. One module drives 3 V pulses into 50 Ω on every output over the agreed frequency range, with the DC level set per output.

    3. P2

      Two-module sync

      Two modules

      Goal. Show that two modules sharing REF, SYSREF and TRIG put their pulses out at a known, repeatable skew.

      Tasks

      • Build sync unit v1: 10 MHz OCXO into an LMK04832, with REF 10 MHz and SYSREF 5 MHz out on phase-matched coax.
      • Run multi-tile sync (MTS) across two cards from the shared SYSREF.
      • Gate the pattern start with TRIG and check that every power-up starts on the same fabric cycle.
      • Measure output-to-output skew between the two modules and settle the calibration method.

      Open items

      Exit gate. The skew between two modules repeats across power cycles, and the chosen calibration method removes it.

      Stages Sync & timing Scaling
    4. P3

      Four-module array

      Four modules

      Goal. Scale to the full array of 32 DAC columns and 32 one-bit rows.

      Tasks

      • Build four carriers from the P1 design with the P2 fixes folded in.
      • Pick bench or rack mechanics and mount the cards, carriers and sync unit.
      • Size and wire the 12 V supply for the whole array.
      • Cable REF, SYSREF and TRIG as a phase-matched star, and GbE from each module to the PC.

      Open items

      No open items yet. Items found in P0 to P2 that affect the array go here.

      Exit gate. All 64 outputs play one pattern, in step, under control from the PC.

    5. P4

      Calibration and DUT integration

      Full array

      Goal. Turn the array into an instrument the experiment can drive.

      Tasks

      • Measure and store a skew table for every channel.
      • Measure and store an amplitude table for every channel.
      • Measure warm-up drift and set how long the array warms up before calibration.
      • Define the software API on the PC: load patterns, set DC levels, arm and trigger.
      • Connect the DUT and run the first pulse sequence.

      Open items

      No open items yet.

      Exit gate. The DUT sees calibrated pulses on every channel from one software call.
